# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Build, test, verification stages, manual rfsim runs and repo conventions live in AGENTS.md —
follow it. This file adds detail on top of it.

@AGENTS.md

## Build details

- CMake presets (`CMakePresets.json`):
  - `cmake --preset default` → `cmake_targets/ran_build/build` (RelWithDebInfo)
  - `cmake --preset tests` → `cmake_targets/ran_build/build_test` (`ENABLE_TESTS=ON`, ASan on)
  - build presets `5gdefault` (nr-softmodem, nr-uesoftmodem, rfsimulator, dfts, ldpc,
    params_libconfig, params_yaml), `4gdefault`, `tests`.
- Radio devices, LDPC, DFTs and config backends are **separate shared libraries** loaded at
  runtime (`common/utils/load_module_shlib.c`). `ninja nr-softmodem` rebuilds `ldpc`/`ldpc_orig`
  (explicit dependencies) but **not** `rfsimulator`, `dfts`, `params_libconfig`, `params_yaml` —
  build those too when they changed or are missing.
- Useful CMake options: `-DENABLE_TESTS=ON`, `-DENABLE_PHYSIM_TESTS=ON`,
  `-DSANITIZE_ADDRESS=ON` (also `SANITIZE_THREAD`, `SANITIZE_UNDEFINED`, `SANITIZE_MEMORY`),
  `-DE2_AGENT=ON` (see FlexRIC below), `-DT_TRACER=ON` (default), `-DCMAKE_BUILD_TYPE=Debug`.
- ASN.1 codecs (RRC, NGAP, F1AP, E1AP, XnAP, …) are generated by `asn1c` at build time; a
  compatible `asn1c` is installed by `./build_oai -I` (or `-DAUTO_DOWNLOAD_ASN1C=ON`).
- ASan binaries: run with `sudo LD_LIBRARY_PATH=. ./nr-softmodem ...`. If ASan crashes with
  `DEADLYSIGNAL` (even during the build), `sudo sysctl vm.mmap_rnd_bits=30`
  (`doc/dev_tools/sanitizers.md`).

## Testing details

- Unit tests are only built with `-DENABLE_TESTS=ON`; `ninja tests` builds all of them.
- `ctest -N` lists tests; `ctest -R <regex> --output-on-failure` runs a subset;
  `ctest -L <label>` / `--print-labels` for labels; `-j N` for parallelism.
- Inspect a physim's actual command without running it: `ctest -R nr_ulsim -N -V` (look at
  `Test command:`; options are `;`-separated in `TEST_CMD`). Physims can then be run directly
  from the build dir, e.g. `./nr_ulsim -n100 -R106 -r106 ...`; `-P` prints timing for
  `nr_dlsim`/`nr_ulsim`.
- Tests live next to the code they test (e.g. `openair2/RRC/NR/tests`,
  `openair2/LAYER2/nr_pdcp/tests`, `openair2/F1AP/tests`, `common/config/tests`), not in a central
  directory. The parent `CMakeLists.txt` guards `add_subdirectory(tests)` with
  `if(ENABLE_TESTS)`; the `tests/CMakeLists.txt` itself then does:

  ```cmake
  add_executable(my_test mytest.c)
  add_dependencies(tests my_test)
  add_test(NAME my_test COMMAND my_test)
  ```

  GoogleTest is available (`GTest::gtest` / `GTest::gtest_main`).
- Physim tests are registered in `openair1/SIMULATION/tests/CMakeLists.txt` (only added when
  `ENABLE_PHYSIM_TESTS=ON`) with
  `add_physim_test(physim.<4g|5g>.<exec>.test<N> "<description>" <exec> <options...>)`
  (`cmake_targets/macros.cmake`). Timing limits are attached with `check_threshold(...)` /
  `check_threshold_range(...)` in files passed via `-DPHYSIM_CHECK_FILES`; every test runs
  through `RunTimedTest.cmake`. The `add_timed_physim_test` mentioned in
  `doc/physical-simulators.md` no longer exists. The `quick_physim` label marks a fast subset.
- Physim sources: `openair1/SIMULATION/NR_PHY/` (5G: `nr_dlsim`, `nr_ulsim`, `nr_pucchsim`,
  `nr_prachsim`, `nr_pbchsim`, `nr_srssim`, `nr_psbchsim`, …), `openair1/SIMULATION/LTE_PHY/`
  (4G), `openair1/PHY/CODING/TESTBENCH/` (`ldpctest`, `polartest`, `smallblocktest`).
- CI testcases: `ci-scripts/xml_files/*.xml` (e.g. `container_5g_rfsim.xml`,
  `container_5g_f1_rfsim.xml`, `container_5g_e1_rfsim.xml`, `container_5g_rfsim_n2_ho.xml`,
  `container_5g_flexric_rfsim.xml`), run via `ci-scripts/run_locally.sh` as in AGENTS.md. The
  orchestrator is `ci-scripts/main.py`, the matching docker-compose setups are in
  `ci-scripts/yaml_files/`, and CI-tested gNB/UE configs are in `ci-scripts/conf_files/`.

## Formatting

- `git clang-format` reformats only staged changes using the root `.clang-format`
  (`doc/clang-format.md`). An optional hook is in `pre-commit-clang` (copy to
  `.git/hooks/pre-commit`).
- If the older OAI coding-guidelines document and `.clang-format` disagree, `.clang-format` wins.
- Don't commit commented-out code.

## Architecture

### Executables (`executables/`)

- `nr-softmodem` — 5G gNB. One binary covers monolithic gNB, CU, DU and CU-CP; the role comes
  from the config file. `nr-cuup` is the standalone CU-UP.
- `nr-uesoftmodem` — 5G UE (can run several UEs in one process with `--num-ues`).
- `lte-softmodem`, `lte-uesoftmodem` — 4G eNB/UE.
- gNB modes: SA (default), `--nsa`, `--phy-test` (no RA), `--do-ra` (RA without core/RRC
  connection), `--noS1` (no core network, inject traffic manually). `--rfsim` selects the RF
  simulator instead of real hardware (`doc/RUNMODEM.md`, `doc/runmodem-nrue.md`).

### Layer map

| Layer | gNB | UE |
|---|---|---|
| PHY | `openair1/PHY/NR_TRANSPORT`, `NR_ESTIMATION`, `NR_REFSIG`, `CODING`; scheduling of L1 in `openair1/SCHED_NR` | `openair1/PHY/NR_UE_TRANSPORT`, `NR_UE_ESTIMATION`, `openair1/SCHED_NR_UE` |
| MAC | `openair2/LAYER2/NR_MAC_gNB` | `openair2/LAYER2/NR_MAC_UE` |
| RLC / PDCP | `openair2/LAYER2/nr_rlc`, `nr_pdcp` (shared by gNB and UE) | same |
| SDAP | `openair2/SDAP` | same |
| RRC | `openair2/RRC/NR` | `openair2/RRC/NR_UE` |
| NGAP / NAS | `openair3/NGAP` | `openair3/NAS` (5G NAS), `openair3/UICC` |
| GTP-U / SCTP | `openair3/ocp-gtpu`, `openair3/SCTP` | — |
| F1AP / E1AP / XnAP | `openair2/F1AP`, `openair2/E1AP`, `openair2/XNAP` | — |
| E2 agent | `openair2/E2AP` | — |
| Radio | `radio/` (rfsimulator, vrtsim, USRP, fhi_72, zmq, …), `fronthaul/` | same |

Legacy 4G code sits in the non-`NR` siblings (`openair1/PHY/LTE_*`, `openair2/LAYER2/MAC`,
`openair2/RRC/LTE`, `openair3/S1AP`, …). `common/` holds shared infrastructure (config, LOG,
T tracer, thread pool, ITTI, time manager, telnet server).

### ITTI — inter-task messaging (`common/utils/ocp_itti`)

Higher layers (RRC, NGAP, F1AP, E1AP, X2AP/XnAP, SCTP, GTP, …) run as ITTI tasks exchanging
typed messages via `itti_send_msg_to_task` / `itti_receive_msg`. Message IDs and payload structs
are declared in `openair2/COMMON/*_messages_def.h` / `*_messages_types.h`; the receiver frees the
message. ITTI also offers fd subscription and timers that post messages. Adding a message means
adding it to both the `_def.h` and `_types.h` of the relevant interface.

### gNB RRC (`openair2/RRC/NR`)

RRC is a single-threaded ITTI task (`rrc_gnb_task()` in `rrc_gNB.c`) that processes messages in
FIFO order in a big switch over `NGAP_*`, `F1AP_*`, `E1AP_*` messages (plus `X2AP_*`, `XNAP_*`,
`NRPPA_*`, `NR_RRC_*` and `TIMER_HAS_EXPIRED`); handler names follow the 3GPP message names.
It is split into files by concern: UE context (`rrc_gNB_UE_context.c`), NGAP
(`rrc_gNB_NGAP.c`), DU/cell management (`rrc_gNB_du.c`, `rrc_cell_management.c`), CU-UP
(`rrc_gNB_cuup.c`), mobility/handover (`rrc_gNB_mobility.c`), measurements, NR-DC, NSA, NRPPa.
`doc/RRC/rrc-dev.md` has sequence diagrams for registration, reestablishment, PDU session
setup/modification/release, F1 and N2 handover and paging, mapped to the functions involved.

### Functional splits: same code path, different transport

F1 (CU↔DU) and E1 (CU-CP↔CU-UP) messages are **always** used internally, even in a monolithic
gNB. Only the transport differs, selected at runtime through function-pointer interfaces:

| Direction | Interface header | Monolithic | Split |
|---|---|---|---|
| RRC → MAC (F1 DL) | `RRC/NR/mac_rrc_dl.h` | `mac_rrc_dl_direct.c` | `mac_rrc_dl_f1ap.c` |
| MAC → RRC (F1 UL) | `NR_MAC_gNB/mac_rrc_ul.h` | `mac_rrc_ul_direct.c` | `mac_rrc_ul_f1ap.c` |
| CU-CP → CU-UP (E1) | `RRC/NR/cucp_cuup_if.h` | `cucp_cuup_direct.c` | `cucp_cuup_e1ap.c` |
| CU-UP → CU-CP (E1) | `nr_pdcp/cuup_cucp_if.h` | `cuup_cucp_direct.c` | `cuup_cucp_e1ap.c` |

The node type is derived from the config in `get_node_type()` (`GNB_APP/gnb_config.c`):
- DU: `MACRLCs.[0].tr_n_preference = "f1"`.
- CU: `gNBs.[0].tr_s_preference = "f1"`. A plain CU uses F1AP plus **direct** E1.
- CU-CP: a CU plus an `E1_INTERFACE` with `type = "cp"`. `nr-cuup` is always CU-UP.
- On the CU-UP side the transport is chosen in `nr_pdcp_e1_if_init()` (`nr_pdcp_oai_api.c`).

On the DU side both paths land in the same handlers (`NR_MAC_gNB/mac_rrc_dl_handler.c`); on
CU-UP in `nr_pdcp/cucp_cuup_handler.c`. In the UL/CU-side direction even the "direct" path goes
through ITTI (`mac_rrc_ul_direct.c`), so CU-side handlers are in the `rrc_gnb_task` switch. When
adding or changing an F1/E1 message, update the message struct, both transport implementations,
the handler, and the encode/decode library.

F1AP/E1AP encode/decode libraries (`openair2/F1AP/lib`, `openair2/E1AP/lib`) provide per-message
encode/decode, equality (`eq_*`), deep copy (`cp_*`) and `free_*` functions. The names are not
fully uniform, especially in E1AP, so check the lib header. Their tests
(`openair2/F1AP/tests/f1ap_lib_test.c`, `openair2/E1AP/tests/e1ap_lib_test.c`) do encode → APER
round-trip → decode → `eq_*`; follow this pattern for new messages (`doc/F1AP/F1AP-lib.md`,
`doc/F1AP/F1-design.md`, `doc/E1AP/E1-design.md`).

### gNB MAC scheduler (`openair2/LAYER2/NR_MAC_gNB`)

`gNB_dlsch_ulsch_scheduler()` (`gNB_scheduler.c`) runs every TX slot; UL grants and DL data
are only issued from DL slots. UL scheduling runs first (`nr_schedule_ulsch`, grants for a future
UL slot via K2), then DL (`nr_schedule_ue_spec`). Both share the PDCCH CCE map, so UL DCIs get
priority. Both follow a pipeline of **pluggable function pointers** assigned in `main.c`:
collect candidates (fixed) → RI/PMI (UL: TPMI) → beam → TDA → MCS → RB allocation → dispatch
(fixed) → LCID allocation (DL only). With `--phy-test`, `pre_processor_dl/ul` are replaced by the
phytest versions (`gNB_scheduler_phytest.c`) and the DL policy pointers are not set. Candidates
are `nr_{dl,ul}_candidate_t` (`nr_mac_gNB.h`); policies commit via `COMMIT_ALLOC` /
`COMMIT_UL_ALLOC` (`mac_proto.h`). Default policies are in
`gNB_scheduler_{dl,ul}sch_default_policies.c`. Full details: `doc/MAC/scheduler-architecture.md`.

### MAC ↔ PHY

- gNB: MAC and L1 exchange (n)FAPI structures (`nfapi/`, `openair2/NR_PHY_INTERFACE`). L1 can be
  in-process or behind nFAPI / Aerial (`doc/nfapi.md`, `doc/Aerial_FAPI_Split_Tutorial.md`).
- UE: PHY → MAC via `nr_ue_dl_indication()` / `nr_ue_ul_indication()`; MAC → PHY via
  `nr_ue_scheduled_response()` (`doc/nr-ue-design.md`).

### Real-time threading

- gNB (`executables/nr-ru.c`, `nr-gnb.c`): `ru_thread` reads RF samples (RX timestamps drive
  all timing; TX is stamped in the future) and pushes to `L1_tx_thread`/`tx_func`, which runs the
  MAC scheduler for slot_tx (`ifi->NR_slot_indication` → `run_scheduler_monolithic` →
  `gNB_dlsch_ulsch_scheduler`, `NR_IF_Module.c`), then L1 TX and `ru->fh_south_out`. It then
  triggers `L1_rx_thread`/`rx_func`: PRACH, PUCCH/PUSCH decoding, then `NR_UL_indication`, which
  only passes RACH/UCI/CRC/RX/SRS indications to MAC (it does not schedule). `doc/SW_archi.md`
  and some code comments are stale on this. Segment decoding and other heavy work runs on the
  thread pool (`common/utils/threadPool`).
- UE (`executables/nr-ue.c`, `UE_thread`): initial sync (sync actor) then per-slot processing;
  PDSCH decoding on DL actors; TX for slot n+`NR_UE_CAPABILITY_SLOT_RX_TO_TX` (≥3, may be larger
  if configured by the network) runs on UL actors if any are configured, otherwise inline
  (`common/utils/actor`).
- PDCP and RLC timers (and X2AP in NSA) are driven by 1 ms ticks from the time manager
  (`common/utils/time_manager`; `nr_pdcp_ms_tick`, `nr_rlc_ms_tick` registered in
  `nr-softmodem.c`). The time source is realtime or IQ-sample time for simulation
  (`doc/time_management.md`). RRC timers do not use it; they come from ITTI
  (`TIMER_HAS_EXPIRED`).

### Configuration (`common/config`)

Parameters are declared as `paramdef_t` tables (e.g. `openair2/GNB_APP/gnb_paramdef.h`,
`MACRLC_nr_paramdef.h`, `L1_nr_paramdef.h`; parsed in `gnb_config.c`) and read from libconfig
`.conf` or `.yaml` files (chosen by file extension). Main gNB sections: `gNBs`, `MACRLCs`, `L1s`,
`RUs`, `security`, `log_config`, plus `e2_agent`. Any parameter can be overridden on the command
line: `--gNBs.[0].min_rxtxtime 6`. Sample configs: `ci-scripts/conf_files/` (CI-tested) and
`targets/PROJECTS/GENERIC-NR-5GC/CONF/`.

### Debugging and observability

- Logging: `LOG_E/W/I/D(<component>, ...)` (`common/utils/LOG`); per-module levels in
  `log_config`.
- Asserts: `AssertFatal`, `DevAssert` (`common/utils/assertions.h`). Set `OAI_GDBSTACKS=1` to get
  a gdb backtrace of every thread on assert.
- `OAI_RNGSEED=<n>` seeds the simulation RNG (`randominit()`: physims, vrtsim, rf_emulator) for
  reproducible runs; it has no effect on rfsimulator.
- T tracer (`common/utils/T`) for runtime tracing; telnet server (`common/utils/telnetsrv`) for
  runtime inspection/control; other env vars in `doc/environment-variables.md`.

## FlexRIC / E2 agent (`openair2/E2AP`)

- O-RAN E2 agent embedded in every E2 node type: gNB-mono, CU, CU-CP, CU-UP, DU. Uses the
  FlexRIC git submodule `openair2/E2AP/flexric` (repo `duranta-project/flexric`) for E2AP
  encode/decode. With `E2_AGENT=ON`, CMake runs `git submodule init && update` itself and stops
  with a fatal error if the submodule is still missing.
- Build: `cmake .. -GNinja -DE2_AGENT=ON -DE2AP_VERSION=E2AP_V{1,2,3} -DKPM_VERSION=KPM_V{2_03,3_00}`
  (defaults `E2AP_V2` = v2.03 and `KPM_V2_03`; `E2AP_V1` = v1.01, `E2AP_V3` = v3.01), then
  `ninja nr-softmodem nr-cuup nr-uesoftmodem params_libconfig rfsimulator dfts`.
  **OAI and the FlexRIC nearRT-RIC must be built with the same E2AP and KPM versions.**
- Service-model shared libraries come from building FlexRIC (default install
  `/usr/local/lib/flexric/`); OAI needs them at runtime even if the RIC runs elsewhere.
- Runtime config section:
  ```
  e2_agent = {
    near_ric_ip_addr = "127.0.0.1";
    sm_dir = "/usr/local/lib/flexric/";
  };
  ```
  or `--e2_agent.near_ric_ip_addr ... --e2_agent.sm_dir ...`. Start the RIC with
  `./build/examples/ric/nearRT-RIC` from the FlexRIC build; `XAPP_DURATION` overrides the default
  20 s xApp duration.
- RAN functions (`openair2/E2AP/RAN_FUNCTION`) are registered by `init_ran_func_ag()`
  (`init_ran_func.c`, called from `executables/nr-softmodem.c` and `nr-cuup.c`). Which SMs a node
  exposes depends on its node type (e.g. MAC/RLC only on DU-capable nodes, PDCP/GTP/TC only on
  CU-UP-capable nodes):
  - `O-RAN/ran_func_kpm*.c` — E2SM-KPM v2.03/v3.00, REPORT style 4 (UE-level, condition on
    S-NSSAI); measurements from TS 28.552 (`DRB.PdcpSduVolumeDL/UL`, `DRB.RlcSduDelayDl`,
    `DRB.UEThpDl/Ul`, `RRU.PrbTotDl/Ul`, `CARR.PDSCHMCSDist`, `CARR.PUSCHMCSDist`, `L1M.SS-RSRP`,
    `MR.NRScSSSINR`, `RRC.ConnMean`).
  - `O-RAN/ran_func_rc*.c` — E2SM-RC v1.03: REPORT styles 1 (RRC message copy), 4 (UE RRC state
    change), 5 (UE context info); CONTROL style 1 (radio bearer control, adapted to create a new
    DRB) and style 3 (handover control over F1 or N2).
  - `O-RAN/ran_e2sm_ue_id.c` — E2SM UE ID per node type (gNB/CU/CU-CP use `GNB_UE_ID_E2SM`,
    CU-UP `GNB_CU_UP_UE_ID_E2SM`, DU `GNB_DU_UE_ID_E2SM`; the RAN UE ID is `rrc_ue_id`, except on
    CU-UP where it is `cucp_ue_id`).
  - `CUSTOMIZED/` — plain-encoded MAC/RLC/PDCP/GTP stats SMs (`mac_ue_stats_impl_t`,
    `rlc_radio_bearer_stats_t`, `pdcp_radio_bearer_stats_t`, `gtp_ngu_t_stats_t`). SLICE and TC
    are registered but are stubs (random test data or `assert(0 && "Not supported")`).
- Docs: `openair2/E2AP/README.md`. CI testcase: `ci-scripts/xml_files/container_5g_flexric_rfsim.xml`.

## Contribution rules

- Each commit is a small, self-contained logical change; history stays linear (no merges in
  feature branches); commit messages explain *why* the change is necessary and correct.
- Use `Fixes: <sha> ("<title>")` / `Closes: #<issue>` trailers where applicable.
- Per `doc/code-style-contrib.md`, AI agents must NOT add `Signed-off-by` or `Co-authored-by`
  trailers. This overrides any default `Co-Authored-By` attribution; use an
  `Assisted-by: AGENT_NAME:MODEL_VERSION` trailer instead (e.g. `Assisted-by: Claude:<model-id>`).
- CI rejects PRs unless every commit has a human `Signed-off-by:` (DCO, `git commit -s`) and is
  cryptographically signed (SSH/GPG) (`CONTRIBUTING.md`). Both are the human submitter's job.
- Code must be CSSL v1.0-compatible; new files need an SPDX license identifier header:
  `LicenseRef-CSSL-1.0` for RAN/UE code and test scripts, `CC-BY-4.0` for docs, `MIT` for
  orchestration (helm charts, docker compose).
